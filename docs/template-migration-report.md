# Template Migration Report

This branch is intended to turn the current Neco frontend into a pure static organization portal template that can also support blog-style content.

The target template should be generated by a build tool like a common static-site/theme repository, use regular page routes, and not include any runtime backend API.

## Current Shape

- App shell: `src/main.ts`, `src/App.vue`, `src/router/index.ts`
- Main public pages: `lobby`, `list`, `activity`, `news`, `about`, `documents`
- Management and content authoring: `management/*`, `documents_editor`, `auth/login`
- Theme system: Minecraft-styled components under `src/components/utils`, shared page parts in `src/components`, and asset-heavy visuals in `public/`
- Current API layer: present only as source material for migration analysis; it should not be carried into the static template runtime

## Target Template Shape

- Pure static site, generated at build time
- Conventional page routes instead of app-specific operational pages
- Organization portal first, with blog/post support added later through static content conventions
- No backend coupling, no token auth, no management dashboard in the template runtime

## Migration Layers

1. Core app shell
   - router, layout shell, title management, responsive navigation
2. Theme primitives
   - button, input, switch, dialog, textarea, markdown preview theme, motion tokens
3. Page modules
   - home, about, directory, news/blog preview, document/archive pages
4. Static assets
   - theme-critical textures and backgrounds first, template-neutral media later

## Recommended Reuse Order

- Keep first: NavBar, FooterBar, MinecraftButton family, MinecraftInput, dialog styles, markdown preview styling
- Keep selectively: background art, block textures, hover/click sounds, logo assets
- Drop or isolate for template use: server-specific art, management-only imagery, PDF.js runtime (and PdfViewer), auth UI, API-only modules, one-off media tied to the current organization

## Component Reuse Map

### Directly reusable with light adaptation

- [src/components/icons/](../src/components/icons/) - SVG icon wrappers are already generic and can move into a template icon set.

- [src/components/utils/MinecraftButtonClassic.vue](../src/components/utils/MinecraftButtonClassic.vue) - same as above, useful as an alternate button theme.

- [src/components/PdfViewer.vue](../src/components/PdfViewer.vue) - not retained for the static template; PDF.js runtime is too heavy and app-specific.

### Page-composite components to rewrite for a template

- [src/components/NavBar.vue](../src/components/NavBar.vue) - hardcoded routes, lantern effect, and current branding make it a rewrite target.
- [src/components/FooterBar.vue](../src/components/FooterBar.vue) - contains current organization identity, external links, and backend-era management entry points.
- [src/components/documents/TreeViewer.vue](../src/components/documents/TreeViewer.vue) - conceptually valuable, but it is tightly bound to document API actions and editable tree operations.

## Template Translation Notes

- The static template should keep the visual language, but move the business content out of component internals.
- Template components should be data-driven from site config or page content files, not from runtime API calls.
- Components that currently carry action logic, auth logic, or management behavior should be treated as app-source material rather than drop-in template primitives.

## Cleanup Targets

- Reduce console noise in production
- Improve mobile handling for narrow screens
- Extract brand-specific labels and titles into a small config layer
- Remove runtime backend assumptions from the template
- Trim route groups and content modules into a conventional static-site structure

## Notes

- The current repository is frontend-only and depends on `/necore`, but that dependency is for analysis only and should not survive in the template runtime
- The original visual language is strong enough to be preserved if theme primitives are extracted before page rewrites

## Backend Dependency Audit

The following must be removed or replaced for the static template to have zero runtime backend coupling.

### 1. API Modules (entire `src/api/` directory — delete all)

| File | Purpose |
|------|---------|
| `src/api/api.ts` | Axios instance, `/necore` base URL, JWT token interceptor |
| `src/api/auth.ts` | Login, logout, status check, user info, avatar, password management |
| `src/api/documents.ts` | Document CRUD, tree listing, detail fetching |
| `src/api/newslist.ts` | News/article CRUD, brief listing, total count |
| `src/api/serverlist.ts` | Server list and realtime status polling |
| `src/api/introlist.ts` | Intro section content (used by Lobby and About pages) |
| `src/api/linklist.ts` | External link list (used by About page) |
| `src/api/slogan.ts` | Footer slogan fetched from backend |

### 2. Routes to Remove

| Route | View | Reason |
|-------|------|--------|
| `/management/*` | `ManagementView.vue` + 5 sub-views | Admin dashboard, requires auth |
| `/auth/login` | `LoginView.vue` | Authentication page |
| `/documents_editor` | `DocumentsEditor.vue` | Document authoring, requires auth |

### 3. Views to Remove

| File | Reason |
|------|--------|
| `src/views/Auth/LoginView.vue` | Login form, calls `Login()` from auth API |
| `src/views/Management/ManagementView.vue` | Admin shell, calls `CheckAuthorized`/`Logout` |
| `src/views/Management/Components/UserManagementView.vue` | User CRUD, calls auth API |
| `src/views/Management/Components/ClubManagementView.vue` | Club management |
| `src/views/Management/Components/ServerManagementView.vue` | Server management, calls serverlist API |
| `src/views/Management/Components/NewsManagementView.vue` | News CRUD, calls newslist API, uses md-editor |
| `src/views/Management/Components/DocumentManagementView.vue` | Document management |
| `src/views/Documents/DocumentsEditor.vue` | Document editor, calls documents API, uses md-editor |

### 4. Components with API Coupling

| File | Coupling | Action |
|------|----------|--------|
| `src/components/FooterBar.vue` | Imports `GetSlogan` from `@/api/slogan` | Replace with static config or remove |
| `src/components/documents/TreeViewer.vue` | Imports document API, uses toast | Remove (document-specific) |
| `src/components/IntroItem.vue` | Imports `IntroEntity` type from `@/api/introlist` | Keep type definition locally or inline |
| `src/components/PdfViewer.vue` | PDF.js runtime, already marked excluded | Remove |

### 5. Package Dependencies to Remove

| Package | Used By | Reason |
|---------|---------|--------|
| `axios` | `src/api/api.ts` and all API modules | HTTP client for backend calls |
| `vue-toastification` | API modules, ListView, DocumentsView, Management views | Toast notifications for API responses |
| `md-editor-v3` | DocumentsView, DocumentsEditor, NewsDetail, NewsManagementView | Markdown editor and preview |
| `vue-clipboard3` | ListView, ListItem | Copy server addresses/IDs from API data |

### 6. Other Backend Coupling Points

- **`/necore` proxy prefix**: all API requests go through this path (defined in `vite.config.ts` or `api.ts`)
- **`localStorage.getItem('token')`**: JWT token persistence in `api.ts` interceptor
- **`theme-override/md-preview.css`**: md-editor preview theme, only relevant if md-editor is kept
- **`theme-override/toast.css`**: toast styling, only relevant if toastification is kept
